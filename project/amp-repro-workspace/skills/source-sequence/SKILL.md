# 来源与序列

## 目标与输入

建立“来自哪篇文章、研究哪条序列、有哪些序列证据”的可追溯链；允许结果与作者不同。
只验收本次任务涉及的子任务；已核验的证据可以复用，不因命中此 skill 而重跑整张表。
从当前 case.json 取 accession、source、discovery 和 region，从 STATE.md 取当前任务与已有产物。下文 CASE 表示当前案例目录。
只在核对原文时读取配置里的来源说明/PDF；调用外部搜索时读 [TOOLS.md](../../docs/TOOLS.md) 对应一行。
可用 `python3 scripts/case.py check` 校验已有快照；`fetch` 可抓取 UniProt 与完整 AlphaFold 模型。只需序列、没有模型或需其他接口时可选合适工具，验收仍以输入身份和可追溯产物为准。

## 结果与证据要求

| 子任务 | 必须留下的结果 | 关键判断 |
|---|---|---|
| 原文身份 | 标题、作者、日期、URL、文件哈希；主张对应页码/网页段落 | 拿不到全文就明确缺口，不以同题文章代替 |
| 候选筛选 | 完整查询、过滤条件、数据库版本、原始响应、翻页情况和候选表 | 查询从 discovery 构造；自拟语法要标注，短蛋白列表不等于 AMP 列表 |
| 候选核对 | UniProt JSON、FASTA、序列哈希、长度、物种/菌株、PE 与证据代码、交叉引用 | 核对记录与序列一致；保留未审校与预测来源 |
| 加工注释 | Signal/Chain 实际区间及每项证据 | 已有 SignalP 注释不等于本次重跑或实测；没有注释不猜成熟肽 |
| BLAST | 真实参数、输入序列哈希、数据库、原始结果、摘要表；远端任务保留 job_id | 命中与未检出必须来自完成的任务，不能从请求失败推断阴性 |

BLAST 摘要用 TSV 或 Markdown 表，每行一个命中，含命中 ID、E-value、bit score、identity、比对长度、query coverage 和双方比对区间，注明百分比/比例单位。无命中时保留完整原始结果和零命中说明，不造占位命中。
记录实际生效的参数及选择依据；服务未提供的版本/字段标未知并说明原因。本地运行不要求远端 job_id，以命令、版本和运行记录定位。作者未公开的设置不能填成本次参数。

严格复现原文指定的算法/数据库时，应保留这些比较条件；替代方法的结果另作补充。分析区域由 case 的 region 与当前问题确定；全长或片段都需记录原序列映射、坐标体系和选择依据，不静默截去信号肽。

方法建议：区域未限定时，全长可作基线；判断短序列命中时结合统计显著性与覆盖。可按证据调整方法，无须先执行一次默认配置。

## 保存与完成条件

- 原始搜索与元数据写 `CASE/data/<UTC时间>-<步骤>/`；摘要表写 `CASE/results/`。
- 在 `CASE/EVIDENCE.md` 为每个新结论写主张、证据类别（作者报告/直接观察/推断）、路径和限制。
- 该子任务可设 done 的条件：输入对应配置的对象/区域；原始结果已落盘；实际参数或注释出处可定位；摘要每项判断能回到原始字段或比对记录，缺失项和限制已说明。
- 输入身份、实际参数或原始结果等核心证据缺失时，不能只写一句缺失原因就标 done；“不适用/未知”主要用于执行方式或服务决定的可选字段。
- 在 STATE 更新该步骤、最后核对时间、证据路径和下一步；不能将某一步完成扩展成全流程完成。

## 分支

- accession 变更、合并或序列不符：needs_review，保留实际返回标识，不套旧结果。
- 无模型不妨碍已有 UniProt 证据；结构获取单列 blocked/needs_review。
- 缺配置或远端失败：保存原因与重试条件，标 blocked，不写“无同源”。
- 完成的搜索在说明阈值下无显著命中：done + 未检出；不证明没有近亲或发现新功能。
